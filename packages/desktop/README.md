# @truspec/desktop

An installable desktop app (Windows/macOS/Linux) that wraps the `truspec serve` web UI in a native
window, built with [Tauri](https://tauri.app) v2. It doesn't reimplement any TruSpec logic — it
spawns the real `@truspec/web` server as a background sidecar process and points a native window
at its local URL. See [issue #23](https://github.com/code-with-rashid/truspec/issues/23) for the
full design writeup.

## Prerequisites (contributors only — not needed to use the built app)

Building or running this package locally needs a Rust toolchain, on top of the repo's usual
Node ≥ 22 + pnpm. Nothing else in the monorepo needs Rust — this is scoped entirely to
`packages/desktop`.

1. Install [rustup](https://rustup.rs).
2. Tauri needs a native C/C++ toolchain to link:
   - **Windows**: the "Desktop development with C++" workload from the
     [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
     (this is a multi-GB install; the installer needs to run elevated).
   - **macOS**: Xcode Command Line Tools (`xcode-select --install`).
   - **Linux**: `libwebkit2gtk-4.1-dev`, `libappindicator3-dev`, `librsvg2-dev`, `patchelf` (see
     `.github/workflows/desktop.yml` for the exact `apt-get` invocation).

## Building

```bash
pnpm --filter @truspec/web build      # produces dist/client, dist/server, dist/sidecar — required first
pnpm --filter @truspec/desktop dev    # opens a dev window
pnpm --filter @truspec/desktop build  # produces an installer under src-tauri/target/release/bundle/
```

Both `dev` and `build` run `scripts/prepare-sidecar.mjs` first automatically — it downloads a
portable Node runtime for your current OS/arch (renamed to the target-triple suffix Tauri's
`externalBin` sidecar convention requires) and copies `@truspec/web`'s built sidecar bundle +
client assets in as bundled resources. **A fresh checkout with no `packages/web` build yet will
fail this step** with a clear "run `pnpm --filter @truspec/web build` first" error — that's
expected, not a bug.

`src-tauri/binaries/` and `src-tauri/resources/` are generated by that script and gitignored; so
is `src-tauri/target/` (Rust's own build output). Re-running `prepare-sidecar.mjs` is safe — it
skips re-downloading the Node binary if already staged, but always re-copies the (cheap, local)
web resources.

## Architecture

```
Tauri app (Rust, ~5–10MB shell)
  └─ on launch: read last-opened collection dir from a small persisted config
       (none yet? → native OS folder-picker dialog)
  └─ spawns a bundled sidecar process:
       node  cli-entry.cjs  --dir <collection>  --client-dir <assets>  --port 0  --json
  └─ sidecar prints one line:  {"url":"http://127.0.0.1:54321"}
  └─ Rust reads that line, opens/navigates a native window to that URL
  └─ window closes → sidecar process is killed (no orphaned Node processes)
```

- `scripts/prepare-sidecar.mjs` — stages the portable Node runtime + web resources (see above).
- `src-tauri/src/sidecar.rs` — spawns/kills the sidecar, parses its stdout readiness line, creates
  or navigates the main window.
- `src-tauri/src/config.rs` — persists the last-opened directory (`tauri-plugin-store`) so a
  relaunch doesn't ask again.
- `src-tauri/src/menu.rs` — native "File > Open Collection…" menu item.

## Known v1 limitations (deliberate, see issue #23)

- Installers are **unsigned** — expect an OS warning on first launch (documented in
  [`RELEASING.md`](../../RELEASING.md)).
- No auto-updater — a new version means downloading a new installer.
- Bundles a full portable Node runtime (~80–110MB) rather than a lighter compiled binary, since
  the planned Bun-compiled single-binary CLI (a separate roadmap item) doesn't exist yet. The
  sidecar binary is swappable for that later with no Tauri-side changes.
